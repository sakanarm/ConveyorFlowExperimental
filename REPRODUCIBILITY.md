# Reproducibility guide

## What a reviewer can reproduce

### Exact, seeded simulation reproduction

The simulation tier freezes workloads, policies, teams, resource regimes, arrival/load settings, and 50 paired seeds in `config/main_lock.json`. Common random numbers are used within paired contrasts. A complete run writes append-only event ledgers and derives metrics from those ledgers rather than mutable live state.

```powershell
python -m pip install -r requirements.txt
python -m pytest tests -q
python scripts/download_data.py
python scripts/prepare_data.py
python scripts/run_main.py --check-design
python scripts/run_main.py --workers 8
python scripts/analyze_main.py
python scripts/analyze_secondary_extensions.py --workers 8
python scripts/verify_artifacts.py --output results/main
```

Expected design size: **22,500 runs**. The repository includes `results/main/design.csv`, `metrics.csv`, confirmatory and secondary summaries, figures, integrity reports, and `final_manifest.json`. Per-run event ledgers are excluded from Git because they occupy about 7 GB; they are regenerated by `run_main.py`.

### Real-LLM protocol reproduction

The repository includes the allocation engine, frozen case selection, 60 executable case bundles, deterministic validators, prompts, provider adapter contract, frozen configuration metadata, and analysis scripts.

Run the offline checks first:

```powershell
python -m pytest tests/test_real_llm_*.py -q
python real_llm_pilot/run_pilot.py `
  --config real_llm_pilot/config.mfec_main_frozen.json `
  --cases real_llm_pilot/case_manifest.csv `
  --dry-run
```

Live execution requires a reviewer-supplied API key in the environment and an OpenAI-compatible endpoint configuration. Do not place a key in a JSON file or commit it. Historical generations and wall-clock timing cannot be guaranteed because provider routing, aliases, load, pricing, and backend snapshots may change. The reproducible claim for this tier is therefore the frozen protocol and analysis pipeline, not bit-for-bit output identity.

## Included artifacts

- Source: `Code/`, `scripts/`, `real_llm_pilot/*.py`, and tests.
- Frozen inputs: `config/`, `data/manifest.json`, derived metadata, case bundles, and label packets.
- Method records: protocols, preregistration files, deviation logs, hashes, and source snapshot.
- Simulation evidence: aggregate metrics/effects, statistical summaries, figures, and manifest.
- Real-LLM evidence: validated aggregate tables, statistical summaries, case/engine locks, figures, and calibration/team-selection metadata.
- Communication artifacts: manuscript, editable Draw.io source, and advisor presentation.

## Intentionally excluded from Git

- API keys, `.env` files, bearer tokens, and private credentials.
- Raw Adult, Beijing, and CodeXGLUE data; obtain them through the download script and observe upstream licenses.
- Multi-gigabyte simulation event ledgers and development checkpoints.
- Raw provider call directories, candidate generations, retry state, and wall-clock progress files.
- Caches, rendered QA pages, temporary Office files, local tool runtimes, and editor settings.

## Integrity checks

The analysis package records frozen configuration hashes, case hashes, event-ledger hashes, source snapshots, and final manifests. Before publication, create a tagged GitHub release and a DOI-backed archive containing any large event-ledger bundle that the journal requires. Record the release commit and DOI in the manuscript.

## Recommended archival release

1. Tag the reviewed commit, for example `v2.0.0-paper`.
2. Deposit the tag plus optional compressed event ledgers in Zenodo or OSF.
3. Add the DOI and immutable commit SHA to the manuscript.
4. Preserve provider execution dates, model aliases, observed metadata, price source, and configuration hashes.
