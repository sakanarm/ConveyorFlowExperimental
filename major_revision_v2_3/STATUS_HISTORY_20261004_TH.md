# ConveyorFlow v2.3 — ประวัติสถานะก่อนกู้ Podman (เก็บไว้ตรวจย้อนหลัง)

อัปเดต 4 ตุลาคม 2026. เอกสารนี้เป็นสถานะการทำงานและบันทึก feasibility pilot สองเคส ไม่ใช่ผลเปรียบเทียบนโยบาย Real-LLM และไม่แทน preregistration ใน `ARCHITECTURE_PREREGISTRATION_TH.md` หรือ protocol ใน `../AJSTR Journal/AJSTR_v2_3_MAJOR_REVISION_PROTOCOL_TH.md`.

## สิ่งที่ตรวจผ่านแล้ว

ชุดทดสอบ `python -m unittest discover -s v2/tests -p 'test_*.py'` ผ่าน **70 tests** ณ วันที่อัปเดตนี้. การผ่าน unit tests ไม่ใช่ผลความสำเร็จของโมเดล. `run_ml_dag_llm_feasibility.py` ทำ pilot `ADULT_P0/agent_2` และ `BEIJING_P0/agent_2` จริงแล้ว โดยจำกัดสูงสุด 4 provider calls ต่อเคส; ทั้งสองใช้ 2 calls ก่อนหยุดตาม failure rule. Ingest ผ่าน แต่ preprocessing ที่โมเดลสร้างแปลงข้อมูลประเภท `string` ซึ่งมี `pd.NA` แล้วส่งเข้า `SimpleImputer`; scikit-learn ล้มด้วย `TypeError: boolean value of NA is ambiguous`. บันทึกเป็นความล้มเหลวของคำตอบโมเดลภายใต้ harness นี้ ไม่แก้เงียบ ๆ และไม่อนุมานอัตราสำเร็จจาก n=2. Provider-reported cost ของสอง pilot คือ 0.0112395 และ 0.01127925 ตามลำดับ (ยังไม่อ้างหน่วยสกุลเงินหาก MFEC ไม่ยืนยัน). คีย์ API ใช้ชั่วคราวใน process เท่านั้น ไม่บันทึกลงไฟล์ config หรือ User environment.

หลังสอง negative pilots เพิ่ม prompt revision `v2_missing_values_20261004` สำหรับ **เคสใหม่** เพื่อระบุการจัดการ pandas nullable dtype/missing value อย่างทั่วไป และเพิ่ม Docker daemon + locked-image preflight ก่อน provider call. `ADULT_P1` ถูก materialize/dry-run แล้วแต่ **ยังไม่ execute หรือใช้ API** เพราะ Docker daemon กลับมาไม่พร้อมระหว่าง preflight; เก็บผล P0 เดิมไม่ทับ. ดู `FEASIBILITY_DEVIATIONS_TH.md`. แผนแยก empirical probability ของ v2.3 อยู่ใน `EMPIRICAL_PROBABILITY_PROTOCOL_TH.md`; ขณะนี้ยังไม่มี ecological success-probability estimate.

ตรวจ hash ของ prompt, response, provider metadata, frozen model version และ stage report ของทั้งสอง pilot ผ่าน `audit_ml_dag_pilots.py`; ผลล่าสุดเก็บใน `results/ml_dag_feasibility_audit_v2_20261004.json` (v1 audit คงไว้). Auditor แสดง ingest 2/2 *เมื่อถูกเรียก*, preprocess 0/2 *เมื่อถูกเรียก*, train/package ยังไม่ถูกเรียก และ full job 0/2. ตัวส่วนเหล่านี้เป็น descriptive pilot เท่านั้น ไม่ใช่ parameter estimate ของ simulator.

ฝั่ง BugsInPy เพิ่ม `select_bugsinpy_pilot.py` ที่อ่าน preflight ledger ตามลำดับ frozen selection hash และเลือก 6 cases ที่ครอบคลุมอย่างน้อย 3 repositories แบบ deterministic; หากข้าม candidate หรือไม่มีเหตุผลคัดออกจะปฏิเสธ. ขณะนี้ `preflighted_in_frozen_order=0` และ `selected=[]`: ยังไม่ได้ทดสอบ bug เพิ่มหรืออ้างว่า 6 cases พร้อม. Docker Desktop API ตอบ internal server error และการตรวจ container ผ่าน WSL ค้าง จึงยังยืนยันไม่ได้ว่าไม่มีงาน Docker อื่นกำลังรัน.

หลังจากนั้นผู้ใช้อนุญาตให้หยุด container อื่นได้หากจำเป็น จึงใช้ `DockerCli.exe -Shutdown` แบบ graceful, หยุดเฉพาะ process Docker Desktop/backend ที่ค้าง และเปิด Desktop ใหม่ โดยไม่ลบ container/image/volume. Docker API ยังตอบ 500; `wsl --terminate docker-desktop` ก็ค้างและถูกยกเลิก. ยังไม่รัน MFEC เพิ่ม. หากต้อง restart WSL ทั้งเครื่องหรือ reboot ต้องประเมินผลกระทบต่องานอื่นก่อน. `../REPRODUCE_V2_3.ps1` เป็น entry point สำหรับ offline checks, matched verification, bounded pilot และ audit; `RUN_MATRIX_V2_3_TH.md` แสดง gate/restart rule. เพิ่ม `summarize_ecological_calibration.py` สำหรับ ledger held-out ในอนาคต; **ยังไม่มี ledger calibration ecological จริง**.

หลังผู้ใช้ยืนยันให้ shutdown WSL ได้แล้ว `wsl --shutdown` ก็ยังค้างและถูกยกเลิก; การ restart `WSLService` ถูก Windows ปฏิเสธสิทธิ์. การตรวจ `-Stage LivePreflight` ล่าสุดยังจบที่ `Docker daemon is unavailable; no provider call was made` และ Docker named pipe ไม่มีอยู่. จึงหยุดก่อนใช้ API เพื่อไม่ให้จ่ายเงินสร้างโค้ดที่รันใน container ไม่ได้. ขั้นต่อไปของ real-LLM ต้องกู้ Docker Linux engine (อาจต้องให้ผู้ใช้บันทึกงานแล้ว reboot Windows) แล้วตรวจ locked image; **ไม่มีการรัน generated code บน Windows host แทน**.

วันที่ 5 ตุลาคม 2026 ตรวจ MFEC metadata แบบ read-only เพิ่ม: `results/mfec_metadata_probe_20261005_escalated.json` ยืนยันว่า `/v1/models` ยังแสดง `glm-5.3-flash`, `gpt-5-mini` และ `tencent-hy3`; `/model/info`, `/v1/model/info`, `/model_group/info` ตอบ 401. ไม่มี version mapping หรือราคา input/output ที่ตรวจได้ (`mapping_complete=false`, `pricing_complete=false`). จึงยังห้ามอ้าง model snapshot หรือแปลง provider-reported cost เป็นสกุลเงินโดยไม่มีหลักฐานเพิ่ม. Probe ที่ sandbox network จำกัดอยู่ใน `results/mfec_metadata_probe_20261005.json` เป็น URLError ทั้งหมด; ไม่ใช้เป็นหลักฐานว่า provider ล่ม. ทั้งสองไฟล์ไม่มี credential.

## Gate ที่ยังไม่ผ่าน

1. **G0 — Freeze real-world experiment:** แม้เรียก MFEC ได้ใน exploratory pilot แล้ว ยังต้องตรวจ model aliases/versions, สิทธิ์ใช้ API, ราคาที่เรียกเก็บจริง และเพดานงบ; calibrate ability rank ด้วย held-out end-to-end cases; ล็อก case selection/precision/analysis ก่อนเปิด policy results. คีย์ API ไม่ได้ถูกเก็บถาวรใน environment หรือ repository และไม่ควรบันทึกใน command log.
2. **G1 — Ecological harness:** ML มี container runner แยก 4 stages และ trusted reference ผ่าน Adult/Beijing อย่างละหนึ่งเคสแล้ว; stage-specific LLM generation ต่อใน `run_ml_dag_llm_feasibility.py` และพบ failure จริงใน Adult/Beijing pilot อย่างละหนึ่งเคส. ยังต้องตรวจ model-generated artifacts, leakage/clean replay และรัน pilot หลาย variants. `run_ml_llm_feasibility.py` เดิมยังเป็นคำสั่งสร้างไฟล์ครั้งเดียว จึงใช้แทน DAG end-to-end ไม่ได้. BugsInPy ต้องคัดอย่างน้อย 6 pilot cases จากหลาย repo, ทำ buggy-fail/fixed-pass, hidden regression และ sandbox per case; ตอนนี้มี isolated smoke เฉพาะ tornado#8.
3. **G2 — Architecture control:** matched simulation ผ่านแล้ว แต่ real-tier `CENTRAL_MATCHED` ใน `dag_belt.py` เป็น prototype ของ bid relay เท่านั้น; ยังไม่ได้วัดการสื่อสารจริง หรือสร้าง coordinator failure injection สำหรับ LLM runs. `CENTRAL_FIT` เดิมเป็น global matcher ห้ามใช้แทน matched control.
4. **G3 — Overhead calibration:** วัด serial single-host IPC proxy 1,000 คู่แล้ว: median local 0.10570 ms, central relay 0.20875 ms, paired mean ส่วนเพิ่ม 0.11037 ms (bootstrap 95% CI [0.10825, 0.11238] ms). วัด load sensitivity เพิ่ม 24 sessions/18,000 requests ที่ 1/2/4/8 concurrent clients แล้วด้วย. ดู `OVERHEAD_PROXY_RESULTS_TH.md`. ยังต้องวัด network/provider หรือระบุ local-only scope, แยก queue/claim/relay, lock E1 distribution และทดสอบ fault domains; **G3 ยังไม่ผ่าน**. ห้ามแทนค่า MFEC latency ด้วย proxy นี้หรือค่าที่สมมติแล้วเรียกเป็นผลจริง.
5. **G4 — Feasibility pilot:** อย่างน้อย 4 Adult, 4 Beijing และ 6 reproducible repository bugs ตาม protocol; ตรวจ failures, cost, runtime, contamination และ dependency handoff. ตอนนี้มี MFEC Adult/Beijing อย่างละหนึ่งเคสที่จบด้วย DEAD_LETTER จึงยังไม่ครบ pilot gate.
6. **G5/G6 — Main + manuscript:** หลัง freeze และ pilot จึงรัน paired arms โดยสุ่มลำดับ แล้ววิเคราะห์ job-level outcomes/CI/negative results และปรับบทความ. ยังไม่ควรเรียกว่า Major Revision ปิดแล้ว.

## ความหมายของข้อเปรียบเทียบ

CF-Fit ให้ agent สแกน READY belt, ประเมิน fit/stand-down และ volunteer เอง; atomic claim แก้ชนกันเท่านั้น. Central-Matched ใช้ข้อเสนอ local ชุดเดียวกัน แต่ผ่าน coordinator relay ก่อน claim โดยไม่เพิ่ม candidate pairs หรือ re-rank. Static S3 เป็นการกำหนดเจ้าของแต่ละ stage ล่วงหน้า. ทั้งสามทางใช้ dependency release, verifier, attempt cap และ job accounting เดียวกัน. เมื่อไม่มี overhead/failure การเทียบ CF-Fit กับ Central-Matched ควรให้ assignment/outcome เท่ากัน; ความต่างจริงต้องโยงกับ overhead/failure ที่วัดหรือกำหนดไว้ชัด ไม่ใช่อ้างจากชื่อ architecture.

## ข้อห้ามในการรายงานตอนนี้

- ห้ามเรียก trusted-reference smoke tests ว่า Real-LLM success.
- ห้ามเรียก ML one-shot file generation ว่า four-stage DAG pipeline.
- ห้าม pool microtask results เดิมกับ end-to-end v2.3 หรือรายงานเป็นจำนวน independent datasets.
- ห้ามอ้างว่า ConveyorFlow ไม่มี single point of failure ทั้งระบบ: shared belt/atomic store ยังเป็น dependency ร่วม.
- ห้ามแก้ manuscript v2.2/AJSTR v2.2 ด้วยตัวเลข v2.3 จนกว่า G4–G6 จะผ่านและตรวจผลซ้ำได้.
