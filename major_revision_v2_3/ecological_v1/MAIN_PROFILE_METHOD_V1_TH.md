# Main routing profile: ขอบเขตและที่มา

`build_main_capability_profiles_v1.py` แปลงผล first-attempt calibration ที่ปิดแล้วเป็น **operational routing tier** แยก model × corpus × ML stage (12 specifications ต่อช่อง) และ repair แบบ pooled (6 cases ต่อ model) ก่อนเห็นผล main. เกณฑ์ที่ผู้วิจัยเลือกหลังเห็น calibration แต่ก่อน main คือ Rank 1: VERIFIED < 2/3, Rank 2: 2/3 ถึง < 11/12, Rank 3: ≥ 11/12 ของจำนวนที่วางแผนไว้. Unresolved ยังอยู่ใน denominator. Rank นี้ไม่ใช่ความฉลาดสากล ความใหม่ของรุ่น หรือราคา และห้ามบอกว่าแต่ละ model ต้องอยู่คนละ Rank. เกณฑ์นี้ **ไม่ใช่ preregistration ก่อน calibration**; จึงต้องรายงาน sensitivity ต่อ unresolved-as-verified และ rank-neutral routing.

ข้อมูล ML เป็น conditional isolated-stage observations ที่ใช้ trusted predecessors; ไม่ใช่อัตราสร้าง pipeline ครบ. ข้อมูล repair มีเพียง 6 cases/model จาก 3 repository clusters และ project-specific cells เพียง 2 cases จึงใช้ pooled repair tier อย่างระมัดระวังและรายงานแยก project ภายหลัง. Wilson intervals ของ calibration เป็น descriptive เท่านั้นและไม่ยืนยัน tier ทางสถิติ. ราคาและ token use ต้องรายงานแยกจาก capability.

Difficulty ใน main ใช้ **investigator stage proxy** ที่มีบันทึกก่อน ecological calibration: ingest=1, preprocess=2, train=3, package=2; localized repository repair=2. นี่ไม่ใช่ human-expert หรือ independent LLM ground truth และ stage confounded กับ difficulty; ห้ามตีความผลเป็น difficulty-response curve ภายใน stage. งานยังไหลบน READY belt เหมือนเดิม, agent ที่ว่างประเมิน fit แล้ว volunteer หรือ soft stand-down; matched central ใช้กฎเดียวกันต่างเฉพาะจุดตัดสินใจ. RQ1 รายงาน trade-offs แยก throughput, time, utilization, cost; RQ2 และ ablations รายงานตามจริง ไม่ต้องให้ CF-Fit ชนะทุก metric.
